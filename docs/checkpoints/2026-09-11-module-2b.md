# Module 2B Acceptance Checkpoint

## Goal

在保持 Android 原生、Local-first、无账号和无后端的前提下，为现有 Note 增加可离线使用的多图片能力，并通过非破坏性 Migration 将 Room Schema 从 v1 升级到 v2；不进入 Module 2C。

## Verified Completed

- Note 支持系统 Photo Picker 多选和系统相机 `TakePicture`；Mirra 在系统返回后再次强制单次最多接收 20 张。
- 多图按单张独立执行 import pipeline；损坏或失败图片不会回滚同批次中已经成功的图片。
- 外部 content URI 只用于导入，最终数据库只保存 `images/<uuid>.jpg` 相对路径。
- 图片在临时区完成安全解码、EXIF 方向修正、采样与缩放，最长边不超过 2560px，并以 JPEG quality 88 写入 App 私有目录。
- Note 支持多图缩略图、Caption 500ms 自动保存与生命周期 flush、单图删除和带图片数量提示的 Note 删除确认。
- 全屏预览支持 1–5 倍缩放、平移和当前 Note 内前后切换；知识页提供轻量“全部图片”列表并显示 Caption、所属 Learning Item、Note 页码和创建时间。
- 单图与 Note 删除均使用 move-to-trash、数据库事务、成功 purge、失败 restore；启动清理负责恢复仍有数据库引用的 trash，并清理过期 temp、无引用 trash 和 orphan 文件。

## Schema v2

新增 `image_assets`：

- `id TEXT NOT NULL PRIMARY KEY`
- `noteId TEXT NOT NULL`，外键指向 `notes.id`，`ON DELETE CASCADE`
- `localPath TEXT NOT NULL`
- `caption TEXT NULL`
- `width INTEGER NOT NULL`
- `height INTEGER NOT NULL`
- `fileSize INTEGER NOT NULL`
- `createdAt INTEGER NOT NULL`
- 普通索引 `index_image_assets_noteId(noteId)`
- 唯一索引 `index_image_assets_localPath(localPath)`

`MIGRATION_1_2` 只创建上述表和索引，不修改既有四张表。Schema Export `1.json` 未变化，新增 `2.json`；禁止 destructive migration。

## Data and File Safety

- Migration 测试从导出的真实 v1 Schema 创建数据库，写入 Learning Item、Intent、Session 与 Note 后迁移到 v2，并确认旧字段和值全部保留且新表为空。
- 数据库写入失败时删除本次刚生成的正式 JPEG；文件移动失败时不删除数据库记录；数据库删除失败时恢复已移入 trash 的文件。
- Note 多图删除若中途移动失败，会恢复此前已移动文件；数据库提交后进程被终止时，无引用 trash 由后续启动在 24 小时阈值后清理。
- 数据库仍引用 trash 文件时，下一次启动优先恢复到正式目录；合法引用不会被 orphan cleanup 误删。

## Known Risks

- 文件系统与 SQLite 不能组成真正原子事务；当前通过可恢复 trash、补偿和 24 小时启动清理达到最终一致。
- Photo Picker 的 `ACTION_OPEN_DOCUMENT` fallback 超限由 Repository 再次裁剪并提示，测试覆盖返回超过 20 个 URI；API 37 实机路径使用系统 Photo Picker，未在旧 Android 设备上实际触发 fallback UI。
- 本轮仅有 API 37 模拟器，无实体真机；不同厂商相机应用的 `TakePicture` 兼容性仍需后续真机矩阵验证。

# Module 2C Acceptance Checkpoint

## Goal

在保持 Android 原生、Local-first、Room 2.8.x 与现有单模块架构的前提下，为 Note 增加极轻量 Topic 关联，并提供完全离线、可恢复的 FTS4 全局搜索；不进入 Module 2D。

## Verified Completed

- Topic 支持创建、稳定排序列表、详情、Note 多对多关联、幂等关联/解除和笔记内创建并关联。
- Topic 名称先做 NFKC、去首尾空白与连续空白折叠；数据库唯一索引提供最终重复保护。
- TopicSuggester 只建议正文明确包含且尚未关联的既有 Topic，排除单字，最多 5 条，不使用 AI。
- Search 覆盖 Note 正文、图片 Caption、Learning Item 名称、Topic 名称和非空 Session Summary。
- 中文连续文本生成相邻双字 token，不跨标点；英文保留完整 token；用户原始字符串不拼接进 MATCH SQL。
- 同一 Note 的正文和多张 Caption 聚合成一行搜索文档，因此多处命中仍只返回一个 Note 结果。
- 搜索页 300ms debounce、全局 LIMIT 60，按 Note / Learning Item / Topic / Session 分组并导航到相应详情。

## Schema v3

- `topics(id, name, createdAt)`；`name` 为 `COLLATE NOCASE` 唯一索引。
- `note_topic_cross_refs(noteId, topicId)`；复合主键，双方均为 `ON DELETE CASCADE`，并为 `topicId` 建索引。
- `search_fts(entityType, entityId, searchableText, normalizedTokens)`；Room FTS4、`unicode61`，仅 `normalizedTokens` 参与索引。
- `MIGRATION_2_3` 只新增以上结构；`1.json` 与 `2.json` 未改变，新增 `3.json`，未使用 destructive migration。

## Search Consistency

- 正式业务表是唯一事实源，`search_fts` 是可清空、可重建的派生数据。
- Learning Item、Note、Caption、Image、Topic 和 Session Summary 的现有写路径在原 Room 事务内同步索引。
- 冷启动 `ensureConsistent()` 只比较预期业务对象数与 FTS 行数；相等不等于内容绝对正确。
- 保留显式 `rebuild()`；查询发生 FTS SQLite 异常时最多自动 rebuild 一次并 retry 一次。
- rebuild 幂等且不修改业务表；missing、duplicate 由轻量检查恢复，等行数 stale 内容由显式 rebuild 恢复。

## Known Risks

- FTS 行数健康检查刻意保持轻量，无法发现“行数相同但文本过期”的情况；显式 rebuild 与查询异常恢复是首版补偿路径。
- 中文搜索首版不支持单字、拼音、同义词或模糊匹配；英文为完整 token 精确匹配。
- API 37 设备验证通过，minSdk 23 兼容性由 lint 与不依赖 API 24 的手写 code-point 遍历保证，但尚未在 API 23 实机运行完整矩阵。

## Segment/action matrix

| 当前段 | 3C-1 正式动作 / 观测目标 |
|---|---|
| FOCUS | BREAK；满足连续证据且 FULL 才 DEEP_FOCUS；可信风险确认才 DISTRACTION |
| DEEP_FOCUS | 屏幕重新交互的可信输入降 FOCUS（不是分心）；BREAK；可信风险确认才 DISTRACTION |
| DISTRACTION(A) | 可信退出 → RECOVERY；同当前确认 episode 的用户授权 → ALLOWANCE(A)；BREAK；另一个包 B 重新候选确认 → DISTRACTION(B) |
| RECOVERY | 连续健康正向证据 90 秒 → FOCUS；同关联确认 episode 可授权；BREAK；新风险候选确认 → DISTRACTION 并记录 RECOVERY_INTERRUPTED |
| TEMPORARY_ALLOWANCE(A) | 提前结束/到期 → RECOVERY；一次明确原子转换 → BREAK；B 独立确认 → DISTRACTION(B)，不恢复 A；锁屏/息屏结束授权 |
| BREAK | 健康结束/到期 → RECOVERY；不生成风险确认；重新候选不计休息时间 |
| UNMONITORED / NONE | 可主动 BREAK；休息结束回 UNMONITORED；不出自动 Focus/Stable/Deep/Allowance |

所有已监测类型在真实 loss 时沿用 UNMONITORED + FULL→PARTIAL；PARTIAL 不升 FULL。原低层状态机已有的其他转换并不代表 UI 可绕过新门面。非零切段共享精确 boundary；同刻用户切段拒绝，不虚构 1ms；风险确认沿用零时长保护（原位转换时同时清除旧授权 metadata）。

## Transactions / idempotence / races

- `applyBehavior` 在单一 Room transaction 中复核 Active Session、expectedSegmentId、非空 token、规则快照、时间/风险快照/确认事件身份。关闭旧段与插入新段同事务；插入失败整笔回滚。
- 授权只从 DISTRACTION 或关联 RECOVERY 开始，起点是提交时刻，不改已有分心历史。默认 3/5/5/3 分钟来自 context；单次覆盖范围 1–15 分钟。
- 延长只作用于同一尚未到期 allowance，SQL 条件 `activeSlot=1 / type / extensionCount=0 / plannedEndAt>at`；最多一次加快照的 120 秒。并发、重放、到期后的延长返回拒绝。
- Break 只接受 context 中的 5/10 分钟。主动从 allowance 转 BREAK 是关闭/开启的原子动作，不产生两段重叠。
- deadline 是同一 ClockSample 的 wall/elapsed 配对，运行中只通过 elapsed 计时，延长增量加到原 deadline；到期按原 wall deadline 切断，不把迟到回调补成 FOCUS。
- 命令执行前先结算已知查询超时/时钟跳变，再到期，再复核 Segment/episode。loss、正常 finish、候选确认和用户命令共用既有 controller Mutex；不在事务/事实锁内等待 UI、通知或 DND。
- `RISK_APP_CONFIRMED` 使用确定事件 ID 防重；提示 token 绑定事件，不能把 event.segmentId（源段）误当当前分心段。Recovery 接受授权需保留真实关联，旧 episode 不可任意复用。
- 允许 A 时短访 B 保留 BriefVisit；持续 B 另建候选，确认前再次核对活动 source，结束旧授权。BREAK/已到期授权内的合法时间不借给新候选。
- 同一 prompt 关闭后保留 dismissed 运行状态；返回学习只是关闭/导航选择，不写恢复成功。进程死亡沿用 ABNORMAL，不续旧令牌/授权。

## Continuous evidence / next UI obligations

- 监测查询连续性与正向证据分开；成功空 query 保持前者，不自行证明 Focus。
- `observeEvidence` 只接受新鲜的“屏幕非交互/锁定”或“Session 页面实际可见且有窗口焦点”输入，不能传缓存 package/USER_PRESENT/普通 App/Launcher 当正向。
- 同一 Session、binding、Segment 内持续健康正向证据 90 秒才 Recovery；Stable 只在 FULL + FOCUS 连续 120 秒首次写入；Deep 只在 FULL + FOCUS 连续 900 秒且最近连续非交互 600 秒。
- 中性输入、风险输入、段变化、失监、wall jump/elapsed 倒序或正向样本缺失 ≥6 秒清窗口。查询间隔 ≥6 秒按既有 loss 规则保守降级；仅缺正向证据不凭空制造 monitoring gap。
- 3C-2 必须约 1 秒提供实际证据（也包含中性/失效输入），不可只在窗口头尾输入两次后假定中间连续。页面后台/失焦要立即输入失效；用途界面隐藏时调用 setPromptVisible(false) 暂停等待。状态恢复/倒计时刷新必须使用统一门面，不复制计时到 Compose。
- 本包未接正式 Compose 可见性/设备证据生产者：没有新鲜输入就没有自动 milestone；这是 3C-2/后续接线边界，不是已交付的正式 UI 能力。

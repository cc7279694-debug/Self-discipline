# Phase 1 Checkpoint｜最小学习闭环

## What Was Built

- 创建 Learning Item，记录书名、总页数、当前页和默认 First Action。
- 设置唯一主线；开始首页根据主线、Active Intent、Active Session 显示对应行动入口。
- 完整 Intent → 启动准备 → Session 状态流；Intent 默认 30 分钟超时。
- Session 保存起始页、当前页、结束页、开始与结束时间，界面显示 Session 总时长。
- Session 中连续创建独立 Note，支持摘录、总结、我的理解、问题和可选页码，输入 500ms 后自动保存。
- 正常结束时原子保存 Session、单调推进阅读进度并生成规则式 Summary。
- Learning Item 详情显示保存后的进度与最近一条正常 Session Summary。
- 新进程启动前原子关闭遗留 Active Session 为 `ABNORMAL`，不推进 Learning Item 进度。

## Why

Phase 1 只验证产品最关键的可用闭环：把“我想开始”与“真正开始”分开，并让一次阅读的页码、笔记、结束总结和下一次继续都可靠落在本地数据库。

## Data And Architecture

- 单 App Module，按 `UI → ViewModel → Domain / Service → Repository → Room` 分层。
- Room v1 仅有 `learning_items`、`study_intents`、`study_sessions`、`notes`。
- nullable 唯一槽位保护唯一主线、Active Intent、Active Session。
- 外键使用 `RESTRICT`，所有外键列与核心读取路径均建立索引。
- `stableStartedAt` 保留 nullable，Phase 1 始终不自动写入。
- 初始 Schema 已导出；不存在旧 Room 版本，因此本阶段没有迁移步骤，也未启用破坏性回退。

## Verification Evidence

- JVM 测试覆盖 Intent 超时边界和规则式 Summary。
- API 37 Room 测试覆盖唯一状态、事务转换、非法并发、四类 Note、旧页不回退、异常恢复与文件数据库重开。
- Compose 测试从创建书籍完整操作到两条 Note、结束 Summary，再次打开同一本书验证页码与上次总结。
- 独立恢复探针实际执行 Active Session 写入、App 强停、冷启动，并确认 `ABNORMAL`、Active 清空和正式进度不推进。

## Known Limitations

- 只支持 Phase 1 的文本 Note，不含图片、Topic、搜索或重型编辑器。
- 不含 SessionSegment、Break、Distraction、Recovery，因此不提供有效专注时间。
- 不含 DND、Usage Access、Overlay 或 Stable Start 自动判定。
- Android Studio 未完成系统安装；构建与设备验证使用用户目录中的 JDK、Android SDK、ADB 和 Emulator。

## Next Stage Should Inherit

- 不修改 Phase 1 的事务与唯一状态不变量。
- 后续 Schema 版本必须基于已导出的 v1 Schema 编写并验证非破坏性 Migration。
- Phase 2 只有在用户验收并单独授权后开始。

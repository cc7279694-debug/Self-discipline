## Actual contracts

### Two durable transactions

1. `beginCloseout(sessionId, requestedEndPage, closeoutStartedAt, backwardClockEvidence?)` validates the occupied, learning-qualified Session and latest persisted page. It freezes existing context fields into `PENDING`, closes the active Segment at the final confirmation boundary, and retains the Session slot. A zero-duration active Segment is deleted rather than assigned an invented millisecond. Repeated begin returns the original snapshot.
2. `completeCloseout(sessionId)` reads only that durable snapshot. One transaction writes NORMAL/endedAt/final page, advances Learning Item progress, generates the existing Summary, synchronizes FTS, and marks COMPLETED. Repeated complete returns the existing result. B rollback retains A and its exact boundary for retry.

`CloseoutSnapshot` contains only sessionId / closeoutStartedAt / requestedEndPage and is not an Entity. Repository also exposes get/observe closeout state and snapshot. The old public finishSession bypass is removed.

Normal closeout uses the single final confirmation sample, never completion/retry/cleanup time. The sole backward-clock exception requires actual paired Controller samples belonging to the same binding plus matching durable PARTIAL / monitoringLostAt / active UNMONITORED facts, rechecked inside A. Only then is the safe boundary the maximum of original confirmation time and durable timeline start/boundaries. Generic PARTIAL or a gap string is not proof; ordinary early boundaries still fail.

### Learning guards and cleanup

`ActiveLearningFactGuard` qualifies activeSlot=1, endedAt=null and context ACTIVE inside each relevant transaction. PENDING/COMPLETED reject page, heartbeat, monitoring loss, risk, behavior, milestone, event, receipt and late DND-apply writes. Release metadata remains writable. PENDING remains occupied but cannot be returned/bound by the Intent start fast path.

Finish order is final ClockSample → existing Controller mutex → monitoring settlement → A → session-owned pure runtime invalidation → B → exit mutex → Android cleanup. Episode/prompt/evidence invalidation performs no Android operation. Old query/service-loss/refresh callbacks cannot acquire a new Session's runtime or borrow its clock proof.

Finite NonCancellable durable rechecks cover cancellation whose Room commit returned no result. Android cleanup stays outside Room and the facts mutex. Channels, monitoring release and DND release have independent finite attempts. Caller cancellation propagates; PENDING/B failure cannot reopen reading, and retry does not resample or settle/begin again.

### Startup

PENDING is completed from its original snapshot before ordinary abnormal recovery. B failure remains PENDING and returns PendingRetry, with no FGS restart/new Segment/ABNORMAL rewrite. Intent expiry is independent. Startup still attempts channel cleanup, DND reconcile, image recovery and search bootstrap; one failed owner does not skip later owners. Cancellation runs owned cleanup but does not continue unrelated bootstrap work.

### Confirmation and reconstruction

SessionViewModel tracks delayed debounce separately from in-flight Note/page saves and awaits their actual results. First finish click flushes, then reads the latest durable page and opens confirmation. Preparing/Confirming block edits; Continue samples no end boundary and restores editing. Low final page gets an explicit error rather than a silent clamp.

Final confirmation synchronously enters Saving and samples exactly once before suspension. A failure permits Continue; A success is irreversible. Recreated PENDING shows frozen page/time and retry only: no growing reading timer, Note/page editor, behavior command, evidence or Back-to-reading. Unknown reads are safe read-only errors, not claims that reading has ended; already-known closure remains sticky.

Repeated ACTIVE heartbeat does not unlock a flush. Delayed initial closeout qualification still seeds Note's current-page default. A refresh queued before Saving rechecks the gate before submitting evidence. A cancelled child save is retryable without swallowing actual ViewModel cancellation. The current Composition owns the completion callback, preventing an old Activity callback from consuming Summary navigation. MirraApp's thin PENDING route gate takes priority over delayed restored top-level preference. External finish opens the same confirmation gate; the Composition records each request ID once, so Continue cannot reopen the same already-consumed request.

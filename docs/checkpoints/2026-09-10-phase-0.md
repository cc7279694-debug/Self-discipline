# Phase 0 Checkpoint｜Android 工程基础

日期：2026-09-10

## What Was Built

- 单 `app` Module 的 Android Native 工程，applicationId 为 `com.guanyi.mirra`。
- Kotlin、Jetpack Compose、Material 3 与 Compose-first Navigation 3 基础。
- “开始｜知识｜我的”三栏导航骨架与基础视觉主题。
- 手动 AppContainer 与 Preferences DataStore Repository；保存并恢复最近顶层页面。
- Room 2.8.x 运行时依赖与未来 Schema Export 路径，但未创建任何业务表或空 Database。
- JVM、Instrumented 与 Compose UI 自动化测试基础。
- Gradle Wrapper、Version Catalog、Lint、APK 构建与设备测试流程。

## Why

Phase 0 只建立可运行、可测试、可扩展的最小工程地基，避免在核心学习闭环实现前引入多模块、Hilt 或未来阶段空壳。

## Verification Evidence

- `testDebugUnitTest`：通过，2 个 JVM 测试。
- `connectedDebugAndroidTest`：通过，2 个设备测试，其中包含 Compose Navigation 3 交互。
- `lintDebug assembleDebug`：通过，Debug APK 成功生成。
- API 37 x86_64 模拟器：APK 安装成功，MainActivity 冷启动成功。
- DataStore：切换到“知识”后强制停止并冷启动，仍恢复“知识”页面。
- AndroidRuntime 崩溃日志：验证窗口内无 Mirra 崩溃。

## Key Decisions Inherited

- 单 App Module、按功能分包、手动依赖注入。
- Navigation 3，不回退旧 Navigation Compose。
- Local-first、无账号、无后端、无云数据库。
- Phase 1 不自动判定 Stable Start，不使用固定 Session 时长判定异常。

## Known Limitations

- 当前只是工程与导航骨架，没有 Phase 1 业务功能或 Room Schema。
- 仓库中文路径需要 Android Gradle Plugin 的路径兼容开关。
- Android Studio 未完成系统安装；现有命令行工具链足以构建、测试、安装和运行。
- 首次模拟器冷启动期间 Pixel Launcher 曾短暂无响应；Mirra 正常启动，清除系统弹窗后前台状态与界面验证通过。

## Verified Implementation

### SessionTimelineValidator

只读 `StudySessionEntity + SessionFocusContextEntity? + List<SessionSegmentEntity>`，判定顺序固定：

1. 非 NORMAL、无结束时间或结束不晚于开始 → `SESSION_INELIGIBLE`。
2. 无 Context、非 FULL、存在 monitoringLostAt 或 UNMONITORED → `MONITORING_INCOMPLETE`。
3. 缺段、open / active 段、零或负段长、gap、overlap、首尾不齐、越界、对象关联不符或 checked arithmetic 越界 → `STRUCTURE_INVALID`。
4. 全部满足 → `COMPLETE_TRUSTED`。

对段副本按 startedAt / id 排序，复用未修改的 `SegmentTimelinePolicy.requireValid()`，不复制 gap / overlap 规则，不移动边界。全场与每段差值、有效时长累加使用 checked arithmetic。

- 仅 FOCUS + DEEP_FOCUS 计时，Deep 1:1，不加权。
- BREAK / ALLOWANCE / DISTRACTION / RECOVERY / UNMONITORED 不计 Focus。
- 完整可信但无 Focus 是合法 `0L`；不可用是 `null`，未知不伪装成 0。
- Break / Allowance / Distraction 个数仍为实际段事实；未通过整场资格时不授权未来 UI 冒称完整总次数。
- 旧 Session 不补造 Context / Segment，也不改写历史。

### EffectiveReadingSource / Repository

新增只读接口：

- `SessionDao.observeEndedEntitiesForItemBetween(itemId, fromInclusive, toInclusive)`。
- `FocusDao.observeContextsForSessions(ids)` / `observeSegmentsForSessions(ids)`。
- `ReadingAnalyticsRepository.observeEffectiveRecentForItem(itemId, fromInclusive, toInclusive)`。

先获取范围内、指定书籍的已结束 Session，再以最多 800 IDs 分批，批量读 Context / Segments。父集合 `flatMapLatest`；每代捕获同一父集合，等待所有批次首次值后组合完整 Source，空源不查询 Focus 表，不执行 IN ()。保留旧 / ABNORMAL 原始事实供 Validator 筛选，无每场 SELECT，无 Note / risk label 查询，无分析缓存表。

这是多个反应式 Flow，不是跨表原子事务快照；依赖已冻结的结束后学习事实不可变约束。DND 清理元数据刷新不改变有效指标。缺少事实或 open 段始终保守不可用。

真实 Room QueryCallback 只计本业务的 Session / Context / Segment SELECT。隔离 DB、无并发 fixture 写、首次稳定 Source 的预算为：

| Session 数 | 实际 SELECT 数 | 批次 |
| --- | --- | --- |
| 0 | 1 | 无 Focus 查询 |
| 1 / 40 / 800 | 3 | 1 |
| 801 | 5 | 2 |
| 1601 | 7 | 3 |

预算是 `1 + 2 × ceil(N / 800)`；不是任意规模永远 3 条查询，也不将原 10k 历史测试名当作计数证据。分片全量 Session / Segment 保留，Context / Segment / 父集合变化均实际测试刷新。

### EffectiveReadingService

- 合格速度样本：NORMAL、有结束页、正 Session 时长、endedAt 不来自未来、COMPLETE_TRUSTED 且 effectiveFocusMillis > 0。
- 页差用 Long：`max(0, endPage - startPage)`，不 +1。
- 0 页但正有效时间保留在 Session 数与时间 denominator；可信 0 Focus 保留单场合法值，但不参与速度窗口。
- 依 `AnalyticsTimeContext.now / zoneId`，按结束所属本地自然日选择 7 → 14 → 30 天首个 ≥3 场且 ≥1,800,000ms 有效时长的窗口；不降门槛。
- 速度是 `SUM(pages) × 3,600,000 / SUM(effectiveMillis)`，不是每场速度平均。测试 20 页 / 60min = 20页/h，不是 28页/h。
- 测试 30页 / 30min + 0页 / 15min + 0页 / 15min：3场 / 60min = 30页/h；不能删掉零页样本变成 60页/h。
- 总页数为 0 时窗口可成立、速度是有限 0，但剩余时间为 null；不泄漏 NaN / Infinity。
- 仅 IN_PROGRESS、totalPages > 0、remainingPages > 0、speed > 0 时产生未来有效时间。PAUSED / COMPLETED 保留历史速度，不产生未来时间。
- 剩余页数非负；以整数比值精确向上取整分钟，JDK BigInteger 只保护中间乘法与整除，无新依赖，再显式检查 Long 与 Duration 边界。
- `selectWindow()` 的 null 仅代表样本门槛不足；`estimate()` 仅捕获 ArithmeticException，返回 `ARITHMETIC_OUT_OF_RANGE`，不把溢出冒称样本不足或有效 0，不吞其他异常。
- 上海午夜、跨年、纽约 DST 重复时刻、未来结束时间、3场 / 30min 精确边界和少 1ms、7 / 14 / 30 边界均已测试。
- 本服务不生成自然完成日期，也不含中文 UI 文案。

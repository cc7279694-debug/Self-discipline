## Implementation facts

- 新增 Presenter 纯协调器、Overlay / Notification 平台端、运行态快照与导航、展示事件 Repository、Profile facade / 正式权限入口。既有 AppContainer、Activity、MirraApp、SessionScreen、监测 Runtime/Service 只增加薄展示接线。
- App visible 使用 Activity onStart/onStop，前台只展示已有 in-app prompt；后台要求当前有效 binding、健康查询与可交互/非锁屏设备，不从缓存自行制造风险事实。Prompt 是否有效由冻结 Controller 决定，不因 SystemUI / Launcher / 风险 App exit 而由展示层擅自作废（否则通知栏打开即取消，无法点击）。Foreground package 新鲜度仍由原监测内核处理，与持有已确认 Prompt 的展示渠道分开。
- Session commit 和 monitoring settlement 后读取一次跨应用偏好，随后再执行既有 DND；不把展示/metadata 放进 READY lease，后续开关不改当前快照。失败不改变行为、Coverage 或 DND。
- Overlay 为最大 304dp 宽 / WRAP_CONTENT 的非焦点小窗口，无遮罩、输入框、全屏 intent 或触摸穿透技巧。add/update/remove 在 Main；真实 attach 回执、超时/取消和 generation 防迟到。平台异常降级，移除失败不叠第二 owner。
- 独立 HIGH `mirra_focus_intervention` / notification ID 3002，与 FGS 分离；API33 permission / app notification setting / channel importance 检查。每 episode 最多 post 一次，不绕过 DND，不保证 drawer 可见。
- 四个 Overlay 行为只导航/调用冻结 dismiss：RETURN 调既有 returnToStudy；ALLOWANCE 打开现有理由面板；FINISH 只滚动到正常结束入口；关闭不写 Recovery。显式 immutable Activity PendingIntent 用 session/token/action data URI，Activity decode + runtime submit + consume 复核，迟到/结束/新进程旧动作拒绝。
- Room 写入使用现有 focus_events：SHOWN(IN_APP/OVERLAY) 各一次，UNAVAILABLE 一次；Notification POSTED 不写 SHOWN。事务验证 Active Session、未失监、最新 risk episode、活动 Segment 与当前 runtime token；不修改 Segment 或 coverage。
- 参考当前 Android 官方 BAL 要求：[Background activity launch restrictions](https://developer.android.com/guide/components/activities/secure-bal)。creator/sender 仅在支持 API 使用 opt-in，API36+ 选择 ALLOW_IF_VISIBLE，仅用户点击发送，不自动后台拉起 Activity。
